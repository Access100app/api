Create `public_html/api/scripts/check-links.php` following the validate-dates.php structure and reusing the admin.php curl_multi pattern exactly.

**Script structure:**

```
<?php
/**
 * Check all stored URLs for liveness.
 * Reports broken links classified as permanent (404/410) or transient (5xx/timeout).
 * Read-only — never modifies the database.
 *
 * Usage:
 *   php api/scripts/check-links.php
 */

require_once __DIR__ . '/../config.php';
```

**Step 1 — Query both URL sets:**

Query 1 — meeting detail URLs:
```sql
SELECT id, detail_url, title, meeting_date, source
  FROM meetings
 WHERE detail_url IS NOT NULL AND detail_url != ''
 ORDER BY meeting_date DESC
```
Store result as `$meetings` array.

Query 2 — attachment file URLs (include meeting_id for report):
```sql
SELECT a.id AS attachment_id, a.meeting_id, a.file_url, a.file_name
  FROM attachments a
 WHERE a.file_url IS NOT NULL AND a.file_url != ''
 ORDER BY a.meeting_id DESC
```
Store result as `$attachments` array.

Print header: `echo date('[Y-m-d H:i:s]') . " check-links starting...\n\n";`
Print counts: `echo "--- Checking " . count($meetings) . " detail URLs + " . count($attachments) . " attachment URLs ---\n\n";`

**Step 2 — Build a unified URL list for batching:**

Create a flat `$url_items` array where each element has:
- `url` — the URL to check
- `meeting_id` — for detail_urls: the meeting id; for attachments: the meeting_id foreign key
- `url_type` — `'detail_url'` or `'attachment'`
- `http_status` — populated after check (start as null)
- `curl_error` — populated after check (start as '')

Populate from `$meetings` then from `$attachments`.

**Step 3 — curl_multi batching (copy admin.php pattern verbatim):**

Use `array_chunk($url_items, 20, true)` to split into batches.

For each batch, init curl_multi, create a handle per item (keyed by original index), set the same CURLOPT_* values as admin.php (RETURNTRANSFER, TIMEOUT 15, CONNECTTIMEOUT 10, FOLLOWLOCATION, MAXREDIRS 3, USERAGENT `'Access100-LinkChecker/1.0 (+https://civi.me)'`).

Run the curl_multi event loop (identical to admin.php lines 1846-1857).

After batch completes, collect `curl_getinfo($ch, CURLINFO_HTTP_CODE)` and `curl_error($ch)` back into `$url_items[$index]`. Clean up handles and multi handle.

Add `usleep(250000)` (250ms) throttle between batches to avoid hammering government servers.

Print progress after each batch: `echo "  Checked batch " . $batch_num . "/" . $total_batches . " (" . count($batch) . " URLs)...\n";`

**Step 4 — Classify results:**

After all batches complete, loop through `$url_items` and classify:

- `$http_code >= 200 && $http_code < 400` AND no curl error → healthy
- `$http_code === 404 || $http_code === 410` → permanent failure
- `$http_code === 0` (curl connection error/timeout) OR `$http_code >= 500` → transient failure
- Any other broken status (e.g. 403, 429) → transient failure (not permanent)

Populate three arrays: `$permanent`, `$transient`, `$stats['healthy']` count.

**Step 5 — Print report:**

```
echo "\n\n=== BROKEN LINKS REPORT ===\n\n";

echo "--- Permanent Failures (404/410) --- " . count($permanent) . " URLs\n";
foreach ($permanent as $item) {
    echo "  [PERMANENT] meeting_id={$item['meeting_id']} | status={$item['http_status']} | type={$item['url_type']} | url={$item['url']}\n";
}

echo "\n--- Transient Failures (5xx / timeout / connection error) --- " . count($transient) . " URLs\n";
foreach ($transient as $item) {
    $error_note = !empty($item['curl_error']) ? " | error={$item['curl_error']}" : '';
    echo "  [TRANSIENT] meeting_id={$item['meeting_id']} | status={$item['http_status']} | type={$item['url_type']} | url={$item['url']}{$error_note}\n";
}

echo "\n--- Summary ---\n";
echo "  Total checked:   N\n";
echo "  Healthy:         N\n";
echo "  Permanent (404/410):              N\n";
echo "  Transient (5xx/timeout/error):    N\n";
```

If either `$permanent` or `$transient` is empty, print `  (none)\n` under that section heading instead of a blank block.

Close with elapsed time line matching validate-dates.php format.

**Constraints:**
- No DB writes anywhere in the script
- No HEAD requests — GET only (CURLOPT_CUSTOMREQUEST not set, default GET)
- No `--dry-run` flag needed (this script is inherently read-only)
- Follow the validate-dates.php indentation and style exactly
