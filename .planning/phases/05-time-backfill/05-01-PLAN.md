Create public_html/api/scripts/backfill-times.php modelled exactly on validate-dates.php.

Header docblock:
  Usage:
    php api/scripts/backfill-times.php
    php api/scripts/backfill-times.php --dry-run

Requires:
  require_once __DIR__ . '/../config.php';   // get_db()

CLI args:
  $dry_run = in_array('--dry-run', $argv ?? [], true);

Stats keys:
  'total_checked'    — rows where meeting_time IS NULL or empty AND raw_rss_data IS NOT NULL
  'total_filled'     — rows that received a new meeting_time
  'total_skipped'    — rows that already had a meeting_time (counted, not touched)
  'parse_failures'   — rows where json_decode failed or time regex found nothing
  Per-source sub-keys are acceptable but a single global summary is sufficient.

Query pattern for each source (eHawaii, nco, honolulu_boards):
  SELECT id, meeting_time, meeting_time_end, raw_rss_data, source
  FROM meetings
  WHERE source = ?
    AND raw_rss_data IS NOT NULL
  ORDER BY id DESC

Per-row logic:
  1. json_decode raw_rss_data — if not array, echo [PARSE FAIL] and increment parse_failures
  2. Call extract function (see below) — if returns null time, echo [NO TIME] and increment parse_failures
  3. If meeting_time is already non-null and non-empty → echo [SKIP] (already set), increment total_skipped, continue
  4. If $dry_run → echo "  WOULD FILL: {source} | meeting_id={id} | time_start={H:i:s} | time_end={H:i:s|NULL}"
     Else         → UPDATE meetings SET meeting_time = ?, meeting_time_end = ? WHERE id = ?
                    echo "  FILLED: {source} | meeting_id={id} | time_start={H:i:s} | time_end={H:i:s|NULL}"
  5. Increment total_filled / total_checked

NOTE on NULL vs skip ordering: check existing meeting_time AFTER successful extract, not before, so
the extract function determines whether a time is even present in raw_rss_data.

UPDATE statement for NCO / Honolulu Boards:
  UPDATE meetings SET meeting_time = ?, meeting_time_end = ? WHERE id = ?
  (pass null for meeting_time_end if end regex did not match)

UPDATE statement for eHawaii:
  UPDATE meetings SET meeting_time = ? WHERE id = ?
  (no meeting_time_end column update — eHawaii has no end time)

Maui section: count-only, echo skipped message, no re-parse attempt (raw_rss_data NULL).

Summary block — mirror validate-dates.php format:
  --- Summary ---
    Total checked:      {N}
    Total filled:       {N}  (DRY RUN — no writes) when dry_run
    Total skipped:      {N}  (already had meeting_time)
    Parse failures:     {N}
    Maui skipped:       {N}  (raw_rss_data NULL)

Re-parse functions (defined at bottom of file, after output):

  function extract_nco_hnlboards_time(array $raw): array
    Returns: ['time_start' => 'H:i:s'|null, 'time_end' => 'H:i:s'|null]
    Logic: decode description, split on <br>, strip tags, take line 0,
           detect date-range vs single-date prefix to isolate $time_part,
           apply /(\d{1,2}:\d{2}\s*[ap]m)\s*-\s*(\d{1,2}:\d{2}\s*[ap]m)/i
           strtotime each match → date('H:i:s')

  function extract_ehawaii_time(array $raw): array
    Returns: ['time_start' => 'H:i:s'|null]
    Logic: html_entity_decode description,
           apply /Time:\s*(\d{1,2}:\d{2}\s*[AP]M)/i
           strtotime match[1] → date('H:i:s')
  </action>
